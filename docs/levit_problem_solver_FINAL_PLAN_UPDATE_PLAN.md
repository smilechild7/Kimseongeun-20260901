# 설문 결과 반영을 위한 `FINAL_PLAN` 수정 계획

> 적용 상태: **완료 (2026-09-02)**
> 확정 범위: 통계 갱신 + 사이즈·핏 근거 강화 + 기존 결과의 자동 비교 요약. 사용자 프로필, 확정적 개인 사이즈 추천, 선택형 비교 화면은 제외.

## 1. 대조 기준

- 원본 데이터: `docs/설문결과.csv`
- 전체 응답: 22명
- 타깃 범위 외 `그 외`: 1명 제외
- 35~50세 유효 응답: 21명
- 기존 `FINAL_PLAN`의 분석 기준: 전체 18명, 유효 17명

복수선택 문항은 각 선택지를 고른 응답자 수로 집계한다. 따라서 한 문항의 비율 합계는 100%가 아닐 수 있다. 원문에는 Q8의 최대 5개, Q12의 최대 2개, Q15의 최대 3개 제한보다 많은 선택을 입력한 응답도 있으므로 원본은 수정하지 않고 분석 주석에 이 한계를 명시한다.

## 2. 기존 계획과 달라진 수치

## 3. 제품 결론

전면적인 방향 전환은 필요하지 않다.

```text
조건 기반 탐색
→ 후보 압축과 차이 비교
→ 사진·실물 / 사이즈·핏 / 소재·품질 위험 검증
```

기존의 `조건 기반 탐색이 본체이고 리뷰는 evidence layer`라는 핵심은 새 데이터와도 일치한다. 변경해야 할 부분은 사이즈·핏 위험과 후보 비교의 구현 우선순위를 더 높이는 것이다.

## 4. `FINAL_PLAN` 수정 작업

### P0 — 통계와 문제 정의 바로잡기

1. 문서 기준일을 갱신하고 설문 원본 CSV를 근거 파일로 연결한다.
2. 1.1의 표본을 전체 22명, 유효 21명으로 변경한다.
3. 1.2의 Q9 표와 Q10 분포를 새 집계로 교체한다.
4. 1.3의 반품 원인을 `12/21, 12/21, 6/21, 6/21`로, 여러 날 고민을 `15/21`로 변경한다.
5. 1.4에 실제 행동 빈도를 추가한다: 구매후기 12/21, 사진 후기 11/21, 사이즈표 10/21, 여러 쇼핑몰 비교 10/21, 유사 체형·연령 후기 7/21.
6. 1.5의 Q15 표에 사이즈 추천, 체형 적합성 판단 항목을 추가한다.
7. 1.6의 인터랙션 수치를 갱신한다.
8. README 구조의 `17명 탐색적 설문`을 `21명 유효 응답의 탐색적 설문`으로 변경한다.

### P0 — 사이즈·핏 근거를 MVP의 필수 구매위험 축으로 강화

1. 0장과 2장의 문제 정의에서 구매 불확실성의 세 축을 `사진·실물`, `사이즈·핏`, `소재·품질`로 명시한다.
2. Product Card에 `사이즈·핏 참고` 영역을 독립적으로 두고 다음을 표시한다.
   - 판매 옵션과 확인 가능한 사이즈표 정보
   - 리뷰의 작게 나옴/정사이즈/크게 나옴 신호
   - 실제 메타데이터가 있을 때만 유사 체형 후기
   - 근거가 부족하면 `판단할 정보 부족` 표시
3. 상품 원본 스키마와 DB에 nullable `sizeGuideText`를 추가한다. 크롤러가 얻은 사실만 저장하고 LLM이 치수를 생성하지 못하게 한다.
4. 별도 `fitContext`나 사용자 프로필은 추가하지 않는다. 평소 사이즈와 체형 고민은 원문 `query` 및 기존 `sizes`, `fitTags`, `keywords` 안에서만 soft context로 해석한다.
5. 리뷰 수집 시 `optionText`와 공개된 키·평소 사이즈 등 reviewer metadata를 가능한 경우 수집한다. 데이터가 없을 때는 유사 체형 표현을 금지하는 기존 원칙을 유지한다.
6. 평가 케이스에 평소 사이즈, 체형 고민, 여유/타이트 선호가 포함된 질의를 추가한다.

### P1 — 후보 비교를 결과 UX에 명시

1. 별도 `compare_products` tool은 추가하지 않는다. `search_products`가 반환한 최대 3개 후보를 같은 기준으로 정렬해 비교한다.
2. 결과 카드 또는 모바일 비교 화면에서 가격, 핏, 소재, 사이즈 옵션, 사진·실물 신호, 핵심 우려를 같은 순서로 보여준다.
3. 선택형 비교 화면은 만들지 않고 추천 결과 2~3개의 `bestFor`와 `tradeoff`를 자동 비교한다.
4. Q16의 1위인 조건 선택 UI와 자연어 refinement는 그대로 유지한다.

### P2 — 후속 검증 대상으로 보류

자유응답에는 보유 옷 기반 코디, 전체 코디, 가상 착용, 체형별 실착 이미지 요구가 반복된다. 다만 Q15에서 `가지고 있는 옷과 코디하기 좋은 상품`은 1/21이고, 옷장·코디·가상 피팅은 데이터와 구현 범위가 크게 늘어난다. 따라서 기존 Non-goal을 유지하고 후속 인터뷰/프로토타입 검증 항목으로만 기록한다.

## 5. 수정하지 않을 핵심 결정

- 조건 기반 탐색이 제품의 본체라는 결정
- 리뷰를 추천 검증 evidence로 사용하는 구조
- 쇼핑 검색 UI를 중심으로 자연어를 보조 수단으로 쓰는 방향
- 여러 쇼핑몰의 실제 상품만 추천하는 원칙
- 근거가 없을 때 사이즈·핏을 보장하지 않는 원칙
- MVP에서 회원가입, 장기 프로필, 옷장, 코디 추천, 가상 피팅을 제외하는 결정

## 6. 적용 순서와 완료 기준

1. P0 통계 교체와 데이터 한계 주석
2. P0 사이즈·핏 데이터 계약, 카드, Agent 규칙, 평가 케이스 반영
3. P1 비교 UX는 기존 검색 결과의 자동 비교 요약으로 적용
4. 문서 전역에서 `17명`, `9/17`, `12/17` 등 구 수치가 남아 있지 않은지 검색
5. 모든 새 수치가 CSV에서 재현되는지 검산

`FINAL_PLAN`의 제품 방향은 유지하면서 새 설문이 강하게 보여준 사이즈·핏 실패와 비교 요구를 구현 범위·데이터 스키마·UI·평가에 반영했다.
